> *English translation of [LingoFuse_Ruby_ABI_Integration_Report.md](LingoFuse_Ruby_ABI_Integration_Report.md).*

> **Document purpose**: records the whole process of adding Ruby ABI generation support to the `code_decl_to_abi` tool chain, including deliverables, base-library fixes, key design decisions, test verification results and remaining issues.
> **Date written**: 2026-10-27
> **Status**: passed multi-language interoperability testing (Pascal call → Ruby service / Ruby call → Ruby service all PASS)

## 1. Work objective

Add a complete Ruby ABI generation chain to LingoFuse, so that Ruby can interoperate with Pascal / C++ / Rust / Python / C# / Java / Node.js / TypeScript / Erlang / Julia / Zig / Swift over the same ABI interface.

**Acceptance criteria**:
- Automatically generate Ruby service / call code from any Pascal unit or C header file
- A Ruby service can be called by call sides of other languages such as Pascal / C++ / Rust
- A Ruby call can call services generated by any other language
- All ABI function variants available (App / UID / P2PName, sync / async / sequenced)
- service + call interoperate in both directions, all tests PASS

## 3. Base-library fix details

### 3.1 `DataHandle#raw` type inconsistency (🔴 blocking)

**Problem**:
- The C extension `LingoFuse::Native.lf_*` parses handles via `NUM2ULL(v)` and only accepts `Integer`
- But `DataHandle#raw` returns `Fiddle::Pointer` on the Fiddle path
- Result: `LingoFuse::Native.lf_get_p2p_uid(handle.raw)` raises `TypeError`

**Fix**: normalize at the end of the `raw` method:

```ruby
def raw
  return nil if @handle.nil?
  @handle.respond_to?(:to_i) ? @handle.to_i : @handle
end
```

### 3.2 `DataHandle` missing `p2p_uid` / `p2p_name` (🔴 blocking)

**Problem**: the `DataHandle` of C++ / Rust / Pascal all have methods to read the sender's UID / P2P name; Ruby lacked them. Service-side callbacks could not identify the caller.

**Fix**: add two methods to `DataHandle`, with safe degradation (returns `nil` / `''` when `Native` is absent):

```ruby
def p2p_uid
  ensure_not_disposed!
  return nil unless defined?(LingoFuse::Native)
  r = raw
  return nil if r.nil?
  LingoFuse::Native.lf_get_p2p_uid(r)
rescue StandardError
  nil
end

def p2p_name
  ensure_not_disposed!
  return '' unless defined?(LingoFuse::Native)
  r = raw
  return '' if r.nil?
  LingoFuse::Native.lf_get_p2p_name(r) || ''
rescue StandardError
  ''
end
```

### 3.3 `Framework` missing `check_app` / `check_api` (🟠 serious)

**Problem**: `LingoFuse::Status` has `check_app` / `check_api`, but `LingoFuse::Framework` did not. The generated test code raised `NoMethodError` when calling `Framework.check_api`, which crashed call_test.

**Fix**: add two forwarding methods to `framework.rb`:

```ruby
def check_app(app_name)
  ptr = LingoFuse.cstr_ptr(app_name)
  LingoFuse::LF_CheckApp.call(ptr) != 0
end

def check_api(app_name, api_name)
  app_ptr = LingoFuse.cstr_ptr(app_name)
  api_ptr = LingoFuse.cstr_ptr(api_name)
  LingoFuse::LF_CheckApi.call(app_ptr, api_ptr) != 0
end
```

### 3.4 Dangling dispatcher thread causes a `$C0000005` crash (🔴 blocking)

**Problem**:
- When the Ruby process exits abnormally (uncaught exception), the `NativeBridge` dispatcher thread is still running C code inside `wait_for_work` / `process_all`
- `LingoFuse64.dll` disappears with the process (never called `free_library`)
- The dispatcher thread touches a dangling pointer → Access Violation (`$C0000005`)

**Fix**:

**A. Add a `stop` method to `native_bridge.rb`**:

```ruby
def stop
  @stop_requested = true if defined?(@stop_requested)
  if defined?(@thread) && @thread
    @thread.join(2.0)
    if @thread.alive?
      begin
        @thread.kill
      rescue StandardError
      end
      @thread.join(0.5)
    end
    @thread = nil
  end
  @started = false
  nil
end
```

The dispatcher loop now checks `@stop_requested`:

```ruby
loop do
  break if @stop_requested
  begin
    wait_for_work(100)
    break if @stop_requested
    process_all
  rescue StandardError => e
    warn "[NativeBridge] dispatcher error: #{e.class}: #{e.message}"
  end
end
```

**B. Add an `at_exit` block to `lingofuse.rb`** (strict order):

```ruby
at_exit do
  # 1. Stop the dispatcher thread (must stop first, otherwise it will access the unloaded DLL)
  LingoFuse::NativeBridge.stop rescue nil

  # 2. Stop the simulated main thread
  LingoFuse::Framework.exit_main_thread rescue nil

  # 3. Clear the App pool, release handles, unload the IPC library
  LingoFuse::Framework.shutdown rescue nil

  # 4. Finally unload LingoFuse64.dll
  LingoFuse::Native.free_library rescue nil
end
```

The **cleanup order** is a hard constraint:
- **The dispatcher thread must be stopped first**, otherwise it will touch a dangling pointer after `LingoFuse64.dll` is unloaded
- **The DLL must be unloaded last**, otherwise the dispatcher thread still references functions inside the DLL

## 4. Wire protocol design (the core of cross-language interoperability)

The generated Ruby code is **byte-for-byte aligned** with the Pascal / C++ / Rust generators, ensuring that the service / call of any two languages can call each other.

### 4.1 Request / response format

| Position | Content |
|------|------|
| **Request payload** | A plain sequence of parameters (`int32` / `int64` / `string` / ...), no status byte |
| **Response payload** | `[status:u8][result or error string]` |
| **Notify payload** | A plain sequence of parameters (no response check) |

### 4.2 Type mapping table

| ABI type | Ruby parameter | Write function (Ruby side) | Read function (Ruby side) |
|---------|----------|-----------------|-----------------|
| `Integer` / `LongInt` | `int` | `write_int32` | `read_int32` |
| `Int64` | `int` | `write_int64` | `read_int64` |
| `Cardinal` / `DWord` / `LongWord` | `int` | `write_uint32` | `read_uint32` |
| `Word` | `int` | `write_uint16` | `read_uint16` |
| `SmallInt` | `int` | `write_int16` | `read_int16` |
| `Byte` | `int` | `write_uint8` | `read_uint8` |
| `UInt64` | `int` | `write_uint64` | `read_uint64` |
| `Double` / `Extended` / `Real` | `float` | `write_double` | `read_double` |
| `Single` | `float` | `write_single` | `read_single` |
| String family (`string` / `TPascalString` / `PChar` / ...) | `String` | `write_string` | `read_string` |

### 4.3 Scalar endianness

All little-endian:
- `pack('c')` / `pack('C')` — 8 bit
- `pack('s<')` / `pack('S<')` — 16 bit
- `pack('l<')` / `pack('L<')` — 32 bit
- `pack('q<')` / `pack('Q<')` — 64 bit
- `pack('e')` / `pack('E')` — floating point

### 4.4 String encoding

- UTF-8 with a single-byte `#0` terminator
- `write_string` appends `#0` automatically
- `read_string` is tolerant: when there is no `#0`, it reads to the end and sets the position to `size + 1`

### 4.5 Status constants

| Constant | Value | Meaning |
|------|---|------|
| `STATUS_OK` | `0x00` | Success |
| `STATUS_ERROR` | `0xFF` | Failure |

**Error response format**: `[0xFF][error UTF-8 text][#0]`

### 4.6 Key pitfall: procedures do not write a status

**The generators must align**: the Pascal / C++ / Rust generators write **no output bytes at all** for **procedure (no return value)** callbacks. The Ruby generator follows this strictly:

```ruby
def self.callback_ReadOnlyConst(input)
  # ... read parameters ...
  begin
    internal_call_ReadOnlyConst(...)
  rescue StandardError => e
    warn("[callback_ReadOnlyConst] " + e.message)
  end
end
```

**Bad example** (this breaks cross-language interoperability):

```ruby
# ❌ Wrong: a procedure should not write a status
output.write_uint8(STATUS_OK)
```

If the Ruby service side writes `STATUS_OK` for a procedure while the Pascal / Rust call side does not read a status byte, then the byte stream of subsequent calls on the same connection becomes misaligned and everything fails.

## 6. Structure of the generated test scripts

### 6.1 `xxx_abi_service_test.rb` (service side)

**Startup order**:
1. Set options: `quiet(true)` / `overlap_connection(true)` / `wait_connection_ready_ok(false)`
2. Explicitly call `LingoFuse::NativeBridge.start` (a fallback for a missing base-library hook)
3. `reset_prepare` + `prepare_service(ipc:<Unit>_abi, ...)`
4. `Service.create_and_register_abi_app` (registers all ABI APIs internally)
5. Register `LF_TEST_WHOAMI` (Call) + `LF_TEST_ASK_SERVICE_CALL_ME` (Notify)
6. `set_opt_p2p_name` + `register_all_p2p_abi_apis` + register the two test APIs above at P2P level
7. `prepare_client` + `prepare_done`
8. **Block on `$stdin.gets`** (critical: must not exit immediately)
9. Cleanup: `app.dispose` → `exit_main_thread` → `shutdown`

**Special APIs**:

- `cb_whoami`: reads `input.p2p_uid` / `p2p_name` and writes back `[status][uid 32B][p2p_name]`
- `cb_ask_call_me`: uses `input.p2p_uid` to call the client's `LF_TEST_REPORT_SERVICE_IDENTITY` via reverse UID

### 6.2 `xxx_abi_call_test.rb` (call side)

**Startup order**:
1. Set options
2. Explicitly call `NativeBridge.start`
3. `reset_prepare` + `prepare_service`
4. `AppHandle.new(CLIENT_APP_NAME)` + register `LF_TEST_REPORT_SERVICE_IDENTITY`
5. `prepare_client` + `prepare_done`
6. `wait_for_service` (polls `Framework.check_api` 30 times, 200 ms each)
7. `probe_client_identity` (synchronous whoami, parses its own UID)
8. `test_service_initiates_call` (sends `ask_call_me`, waits 10 s for the callback)
9. Iterate over all APIs: 9 function variants / 6 procedure variants
10. Summarize `[PASS]` / `[FAIL]` / `[SKIP]`; `fail == 0` → exit 0, otherwise exit 2

**Exit code convention**:
- `0`: all PASS (SKIPs are allowed, e.g. UID variants skipped because `service_uid` is unavailable)
- `2`: at least one FAIL

## 8. Key decisions in the generator implementation

### 8.1 Why `#39` everywhere instead of `''`

**Lesson**: in Pascal, `''` is an escaped single quote; when concatenating across lines it is easy to miss the closing quote, causing `Fatal: (2001) String exceeds line`.

**Rule**: **ban `''`** in all generator source code; always use `#39 + ... + #39` instead.

**Example**:
```pascal
// ❌ Wrong
Lines.Add('$smoke = ''begin; ...''"');

// ✅ Correct
Lines.Add('$smoke = "' + Inner + '"');
// where Inner := 'begin; require ' + #39 + '$($UnitName)_abi_service' + #39 + '; ...';
```

### 8.2 The capitalization pitfall of Ruby identifiers

**Problem**: in Ruby, identifiers starting with an uppercase letter (`Value` / `Input` / `FileName`) are interpreted as **constants** and cannot be used as parameters or local variables.

**Fix**: append handling at the end of `MakeSafeRubyIdent`:

```pascal
if (Result.Len > 0) and (Result[1] >= 'A') and (Result[1] <= 'Z') then
begin
  Result[1] := SystemChar(Ord(Result[1]) + 32);  // convert to lowercase
  Result := Result + '_param';                    // add a suffix to avoid clashing with internal variables
end;
```

**Effect**:

| Original name | New name |
|------|------|
| `Value` | `value_param` |
| `Input` | `input_param` |
| `FileName` | `file_name_param` |
| `value` (already lowercase) | `value` (unchanged) |

### 8.3 `SystemChar(Ord(...) + 32)` instead of `LowerCase`

**Reason**: `SysUtils.LowerCase(Char)` requires `uses SysUtils`, which the generator's `implementation` section does not have; `Ord` and `SystemChar` come from the `System` unit, so there is zero dependency.

**Correctness**: within the ASCII A-Z range, `Ord(c) + 32` is absolutely the correct lowercase.

### 8.4 The generators do not generate `.md` documentation

As requested by the user, **none of the 4 generators includes a `.md` generation function**. README-style explanations live in the header comments of the test scripts.

## 9. Remaining issues and suggestions

### 9.1 `p2p_registration.rb` missing `NativeBridge.start` (🟡 not fixed)

**Problem**: the `register_api` of `lib/lingofuse/p2p_registration.rb` does not call `LingoFuse::NativeBridge.start`. If a process registers **only** P2P APIs (no App-level APIs), the dispatcher thread never starts, so callbacks queue up when remote calls arrive but nobody consumes them.

**Impact**: `xxx_abi_service_test.rb` calls `NativeBridge.start` explicitly, so **the test path is unaffected**. But a user who writes only a P2P service (with no App-level registration) will hang.

**Suggested fix**: add one line at the start of `register_api`:

```ruby
LingoFuse::NativeBridge.start if LingoFuse::NativeBridge.available?
```

**Current status**: not fixed; the test script compensates. Should be fixed later.

### 9.2 Cross-language combinations not directly verified

Directly verified:
- Pascal call → Ruby service: ✅
- Ruby call → Ruby service: ✅

**Theoretically valid but not measured**:
- Ruby call → Pascal / C++ / Rust service
- Pascal / C++ / Rust call → Ruby service

**Suggestion**: run a cross test once (for example start a Rust service_test and call it from a Ruby call_test) to confirm interoperability.

### 9.3 Suggested additional features

- **Hint improvement in `setup_ruby_tests.ps1`**: when the user passes `-RubyLibDir <root>` instead of `-RubyLibDir <root>/lib`, if `<root>/lib/lingofuse.rb` exists, emit a clear hint. This is already included in the latest `ruby_abi_test_setup_generator_tool.pas`; if your copy is older, regenerate it.

## 10. Usage guide

### 10.1 Generate Ruby code from a Pascal unit

```powershell
# Generate the service side
code_decl_to_abi --lang ruby calculator.pas output\

# Generate the call side
code_decl_to_abi --call --lang ruby calculator.pas output\
```

### 10.2 Build the C extension (first time or after an update)

```powershell
cd D:\CoreLibrary\LingoFuse\ruby
.\setup_build_env.ps1
```

Product: `lib\lingofuse_ext.so`.

### 10.3 Run the tests

**Terminal 1: service**
```powershell
cd output
ruby -I "D:\CoreLibrary\LingoFuse\ruby\lib" -I "." Calculator_abi_service_test.rb
```

**Terminal 2: call**
```powershell
cd output
ruby -I "D:\CoreLibrary\LingoFuse\ruby\lib" -I "." Calculator_abi_call_test.rb
```

**Acceptance**: call_test prints `Pass: N / Fail: 0 / Skip: M` and exits 0.

### 10.4 Call the generated ABI from other Ruby projects

```ruby
require 'lingofuse'
require_relative 'calculator_abi_call'

# Synchronous call
result = Calculator_abi::Call.Add(3, 4)
puts "3 + 4 = #{result}"

# Asynchronous call
f = Calculator_abi::Call.Add_async(3, 4)
result = f.value(timeout_ms: 5000)
puts "3 + 4 = #{result}"

# UID-targeted call
Calculator_abi::Call.Add_uid_call(peer_uid, 3, 4)

# P2PName load balancing
Calculator_abi::Call.Add_p2pname_call('calc_workers', 3, 4)

# Notify
Calculator_abi::Call.Log('hello')
```
