# Swift ABI Code Generator Development Log

> *English translation of [swift_abi_generator_development_log.md](swift_abi_generator_development_log.md).*

> **Document purpose**: this document records the complete development process of adding a Swift language backend to the `code_decl_to_abi` toolchain, including design decisions, the deliverables list, the round-by-round bug fix log and the verification results. It is aimed at future maintainers and AI assistants.
>
> **Reference baselines**: `cpp_abi_*.pas` (C++ backend, the gold standard), `pas_abi_*.pas` (Pascal backend, the reference implementation), `rust_abi_*.pas` (Rust backend, which includes a complete setup + test closed loop)
>
> **Document version**: v1.0
> **Completion date**: 2026-10-27
> **Final status**: Pascal call → Swift service all PASS; Swift call → Swift service all PASS (after fixing the wait loop)

## Chapter 0 Overview

### 0.1 Project goal

Add a **Swift language backend** to the `code_decl_to_abi` toolchain, so that the toolchain can generate a full set of Swift RPC service / call / test / build / setup code from a Pascal/C declaration source, with a **wire format that is exactly identical and interoperable** with the existing 12 languages (Pascal / Python / C++ / Rust / C# / Go / Java / Node.js / TypeScript / Erlang / Julia / Zig).

### 0.2 Deliverables list

| # | File | Responsibility | Artifact |
|:-:|------|------|------|
| 1 | `swift_abi_service_generator_tool.pas` | Service-side generator | `<unit>_abi_service.swift` |
| 2 | `swift_abi_call_generator_tool.pas` | Call-side generator | `<unit>_abi_call.swift` |
| 3 | `swift_abi_test_generator_tool.pas` | Test entry generator | `<unit>_abi_service_test.swift`, `<unit>_abi_call_test.swift` |
| 4 | `swift_abi_test_setup_generator_tool.pas` | Environment setup script generator | `setup_swift_tests.ps1` |
| 5 | `code_decl_to_abi.lpr` (uses clause) | Registration entry | no extra file needed |

### 0.3 Key commitments

- **Generated Swift code contains zero comments** (consistent with the C++/Pascal/Rust output style)
- **No `.md` is generated** (the README generation logic is removed)
- **All single quotes in the Pascal source use the `#39` escape** (avoiding FPC edge-case parsing problems)
- **Wire format aligned byte by byte with C++/Pascal/Rust**
- **Stop and report immediately when a base library problem is found; never cover it up**

## Chapter 1 Architecture design

### 1.1 Three-layer structure

```
┌──────────────────────────────────────────┐
│  Generator layer (.pas)                   │
│  swift_abi_service_generator_tool.pas    │
│  swift_abi_call_generator_tool.pas       │
│  swift_abi_test_generator_tool.pas       │
│  swift_abi_test_setup_generator_tool.pas │
└──────────────────────────────────────────┘
               ↓ generate
┌──────────────────────────────────────────┐
│  Swift artifacts                          │
│  <unit>_abi_service.swift                │
│  <unit>_abi_call.swift                   │
│  <unit>_abi_service_test.swift           │
│  <unit>_abi_call_test.swift              │
│  setup_swift_tests.ps1 (generates         │
│    Package.swift at runtime)              │
└──────────────────────────────────────────┘
               ↓ compile/run
┌──────────────────────────────────────────┐
│  Swift runtime                            │
│  LingoFuse binding (Sources/LingoFuse/*.swift)│
│  C ABI layer (CLingoFuse)                 │
│  LingoFuse native library (LingoFuse64.dll)│
└──────────────────────────────────────────┘
```

### 1.2 Generator registration mechanism

All Swift generators are registered through the `RegisterGenerator` API of `code_decl_to_abi_registry.pas`:

```pascal
RegisterGenerator(
  'swift',                      // language ID
  'xxx_abi_service.swift',      // file name template (xxx replaced by UnitName at runtime)
  gkService,                    // generator kind
  'Swift ABI service implementation',
  @GenerateABIServiceSwiftCode);
```

The `xxx` prefix is replaced at runtime by `ResolveFileName` with the `UnitName` (e.g. `ComplexTestUnit`).

`setup_swift_tests.ps1` is a fixed file name, registered through the `gkPs1` kind, with no `xxx` substitution.

### 1.3 Module organization on the Swift side (enforced by SPM)

`setup_swift_tests.ps1` organizes the generated artifacts into the directory structure enforced by SPM:

```
<out_dir>/
├── Package.swift
├── setup_swift_tests.ps1
├── Sources/
│   ├── <unit>_abi_service/
│   │   └── <unit>_abi_service.swift    ← module name = target name
│   ├── <unit>_abi_call/
│   │   └── <unit>_abi_call.swift       ← module name = target name
│   ├── ServiceTest/
│   │   └── main.swift                  ← executable entry
│   └── CallTest/
│       └── main.swift                  ← executable entry
└── .build/ (generated by swift build)
```

**Key point**: the enum inside `<unit>_abi_service.swift` is named `<Unit>ABIService` (e.g. `ComplexTestUnitABIService`), but the **module name** (the name referenced by `import`) is `<unit>_abi_service` (the target name). **These two are different**.

## Chapter 2 Detailed description of the generated artifacts

### 2.1 Service-side artifact

**File**: `<unit>_abi_service.swift`

**Structure**:

```swift
import Foundation
import LingoFuse

public enum ComplexTestUnitABIService {
    public static let defaultAppName: String = "ComplexTestUnit_abi"
    public static let defaultAppDesc: String = "ABI service for ComplexTestUnit"
    public static let statusOK: UInt8 = 0x00
    public static let statusError: UInt8 = 0xFF

    // internal stub for each Call API (fatalError placeholder)
    public static func internalCall_Add(uid: Uid, p2pName: String, _ a: Int32, _ b: Int32) -> Int32 {
        _ = uid
        _ = p2pName
        _ = a
        _ = b
        fatalError("TODO: implement internalCall_Add")
    }

    // callback for each Call API
    private static func callback_Add(input: DataHandle, output: DataHandle) {
        let uid = input.p2pUid()
        let p2pName = input.p2pName()
        do {
            let a: Int32 = try input.readInt32()
            let b: Int32 = try input.readInt32()
            let result = internalCall_Add(uid: uid, p2pName: p2pName, a, b)
            try output.writeUInt8(statusOK)
            try output.writeInt32(result)
        } catch {
            try? output.writeUInt8(statusError)
            try? output.writeString("\(error)")
        }
    }

    // internal stub + callback for each Notify API (similar structure, no output)

    public static func registerAllABIAPIs(app: AppHandle) throws {
        try app.registerCall("Add", "ABI api for Add", callback_Add)
        // ... (AppHandle.registerCall has no external labels)
    }

    public static func registerAllP2PABIAPIs() throws {
        try P2P.registerCall("Add", description: "ABI api for Add", handler: callback_Add)
        // ... (P2P.registerCall has description:handler: external labels)
    }

    public static func createAndRegisterABIApp() throws -> AppHandle {
        let app = try AppHandle(name: defaultAppName, description: defaultAppDesc)
        try registerAllABIAPIs(app: app)
        return app
    }
}
```

**Key design points**:
- **`internalCall_*` uses a `fatalError` placeholder**: semantically consistent with C++'s `return 0;` / Pascal's `Result := default;` / Rust's `fatalError(...)`. **The user must fill in the business logic by hand**; that is the role of an ABI generator.
- **No `@convention(c)` / `@_cdecl`**: the closure wrapping of `AppHandle.registerCall` is used and the function reference is passed directly.
- **Parameter external labels are `_`**: `internalCall_Add(uid: Uid, p2pName: String, _ a: Int32, _ b: Int32)`, called as `internalCall_Add(uid: uid, p2pName: p2pName, a, b)`.
- **`uid` / `p2pName` are side data**: extracted from `input.p2pUid()` / `input.p2pName()` and passed as leading parameters to `internalCall_*`, so the user knows the caller's identity.

### 2.2 Call-side artifact

**File**: `<unit>_abi_call.swift`

**Structure**:

```swift
import Foundation
import LingoFuse

public enum ComplexTestUnitABICall {
    public static var targetAppName: String = "ComplexTestUnit_abi"
    public static var defaultTimeoutMs: UInt64 = 5000
    public static let statusOK: UInt8 = 0x00
    public static let statusError: UInt8 = 0xFF

    private static func buildParam_Add(_ a: Int32, _ b: Int32) throws -> DataHandle {
        let param = try DataHandle(apiName: "Add")
        try param.writeInt32(a)
        try param.writeInt32(b)
        param.position = 0
        return param
    }

    private static func readResponse_Add(_ resp: DataHandle) throws -> Int32 {
        resp.position = 0
        let status: UInt8 = try resp.readUInt8()
        if status != statusOK {
            let msg = (try? resp.readString()) ?? ""
            throw LingoFuseError.callFailed(
                operation: "ABI call Add failed: " + msg,
                targetApp: targetAppName,
                targetApi: "Add")
        }
        return try resp.readInt32()
    }

    // 9 combinations: App/UID/P2PName × sync/async/async-sequenced
    public static func Add(_ a: Int32, _ b: Int32) throws -> Int32 { ... }
    public static func Add_Async(_ a: Int32, _ b: Int32) async throws -> Int32 { ... }
    public static func Add_AsyncSequenced(_ a: Int32, _ b: Int32) async throws -> Int32 { ... }
    public static func Add_UID_Call(_ uid: Uid, _ a: Int32, _ b: Int32) throws -> Int32 { ... }
    public static func Add_UID_Async(_ uid: Uid, _ a: Int32, _ b: Int32) async throws -> Int32 { ... }
    public static func Add_UID_AsyncSequenced(_ uid: Uid, _ a: Int32, _ b: Int32) async throws -> Int32 { ... }
    public static func Add_P2PName_Call(_ p2pName: String, _ a: Int32, _ b: Int32) throws -> Int32 { ... }
    public static func Add_P2PName_Async(_ p2pName: String, _ a: Int32, _ b: Int32) async throws -> Int32 { ... }
    public static func Add_P2PName_AsyncSequenced(_ p2pName: String, _ a: Int32, _ b: Int32) async throws -> Int32 { ... }

    // 6 combinations of the Notify family
    public static func NoParamProc() throws { ... }
    public static func NoParamProc_SequencedNotify() throws { ... }
    public static func NoParamProc_UID_Notify(_ uid: Uid) throws { ... }
    public static func NoParamProc_UID_SequencedNotify(_ uid: Uid) throws { ... }
    public static func NoParamProc_P2PName_Notify(_ p2pName: String) throws { ... }
    public static func NoParamProc_P2PName_SequencedNotify(_ p2pName: String) throws { ... }
}
```

**Key design points**:
- **Fully exploits the `Target` / `AsyncTarget` abstraction**: `AppTarget` / `UidTarget` / `P2PNameTarget`, keeping the generated code as concise as possible.
- **Async uses native `async/await`**: `await AppTarget(...).callAsync(...)`, no `CheckedContinuation` needed.
- **`buildParam_*` is reused**: Call and Notify share it, avoiding duplication.
- **`readResponse_*` is unified**: status byte + return value, aligned byte by byte with C++'s `EmitCallCheckResponse`.
- **`targetAppName` / `defaultTimeoutMs` are `public static var`**: allowing switching at runtime (aligned with C++'s `ABI_TargetApp`).

### 2.3 Service test artifact

**File**: `<unit>_abi_service_test.swift` (renamed by the setup script to `Sources/ServiceTest/main.swift`)

**Core flow**:

```swift
import Foundation
import LingoFuse
import <unit>_abi_service

func serviceTestRun() -> Int32 {
    var app: AppHandle? = nil
    do {
        Framework.setOption("Wait_Connection_ReadyOk", "False")
        Framework.setOption("Overlap_Connection", "True")
        Framework.setOption("ConsoleOutput", "True")
        Options.setQuiet(true)
        Framework.resetPrepare()
        try Framework.prepareService(listeningAddr: endpoint, physicsAddr: endpoint)
        let createdApp = try <EnumName>.createAndRegisterABIApp()
        app = createdApp
        try createdApp.registerCall("LF_TEST_WHOAMI", "whoami", serviceTestCbWhoAmI)
        try createdApp.registerNotify("LF_TEST_ASK_SERVICE_CALL_ME", "...", serviceTestCbAskCallMe)
        Options.setP2PName(p2pName)
        try <EnumName>.registerAllP2PABIAPIs()
        try P2P.registerCall("LF_TEST_WHOAMI", description: "whoami", handler: serviceTestCbWhoAmI)
        try P2P.registerNotify("LF_TEST_ASK_SERVICE_CALL_ME", description: "ask", handler: serviceTestCbAskCallMe)
        try Framework.prepareClient(physicsAddr: endpoint, app: createdApp)
        if !Framework.prepareDone() { ... return 1 }
        print("[OK] Service ready on \(endpoint)")
        _ = readLine()
        Framework.exitMainThread()
        createdApp.dispose()
        Framework.shutdown()
        return 0
    } catch { ... return 1 }
}

print("=== <unit> ABI service test ===")
if LF_LoadLibrary() != 1 {
    FileHandle.standardError.write("[FATAL] LF_LoadLibrary failed\n".data(using: .utf8)!)
    exit(1)
}
let SERVICE_TEST_EXIT_CODE: Int32 = serviceTestRun()
LF_FreeLibrary()
if SERVICE_TEST_EXIT_CODE != 0 { exit(SERVICE_TEST_EXIT_CODE) }
```

**Bidirectional handshake**:
- `LF_TEST_WHOAMI`: returns the caller's UID + P2PName (extracted from `input.p2pUid()` / `input.p2pName()`)
- `LF_TEST_ASK_SERVICE_CALL_ME`: the Service actively calls the client's `LF_TEST_REPORT_SERVICE_IDENTITY` back with `Framework.callByUid(uid, ...)`

**Key points**:
- **`LF_LoadLibrary` must come before any `LF_*` call** (otherwise everything reports "called before LF_LoadLibrary")
- **`LF_FreeLibrary` is called after `serviceTestRun` returns**
- **Top level explicitly exits with `exit(code)`**, ensuring the exit code is correct

**Async test bridging**:

```swift
final class ResultBox<T>: @unchecked Sendable {
    private let lock = NSLock()
    private var value: Result<T, Error>? = nil
    func set(_ r: Result<T, Error>) { lock.lock(); value = r; lock.unlock() }
    func take() -> Result<T, Error>? { lock.lock(); defer { lock.unlock() }; ... }
}

func runAsyncWithSema<T>(_ label: String, _ body: @escaping () async throws -> T) -> Result<T, Error> {
    let sema = DispatchSemaphore(value: 0)
    let box = ResultBox<T>()
    Task.detached {              // ★ detached escapes the main thread, avoiding main-thread RunLoop dependency
        do { box.set(.success(try await body())) }
        catch { box.set(.failure(error)) }
        sema.signal()
    }
    if sema.wait(timeout: .now() + 10) == .timedOut {
        return .failure(LingoFuseError.timeout(targetApp: label))
    }
    return box.take() ?? .failure(...)
}
```

**Why `Task.detached` + `DispatchSemaphore` is safe**:
- From `Sources/LingoFuse/AsyncSupport.swift`, `callAsync` uses `CheckedContinuation` internally, and the resume is triggered by the C ABI's TCompute worker thread; it does not depend on the main-thread RunLoop.
- `Task.detached` runs on Swift's Cooperative Thread Pool and does not occupy the main thread.
- Blocking the main thread with `DispatchSemaphore.wait` is safe (the test program has no watchdog).

## Chapter 3 Cross-language wire format consistency

This is **the lifeline of multi-language interoperability**; the Swift generator must be byte-by-byte aligned with C++/Pascal/Rust.

### 3.1 Service-side response format

| Scenario | Byte sequence | Swift generated code | C++ counterpart |
|------|---------|---------------|---------|
| Success + integer/float | `[0x00][little-endian bytes of T]` | `try output.writeUInt8(statusOK)` + `try output.writeInt32(result)` | `Safe_Write_Scalar<T>` |
| Success + string | `[0x00][UTF-8 bytes][0x00]` | `try output.writeUInt8(statusOK)` + `try output.writeString(result)` | `Safe_Write_String` |
| Failure | `[0xFF][UTF-8 error bytes][0x00]` | `try? output.writeUInt8(statusError)` + `try? output.writeString("\(error)")` | `Safe_Write_Error` |
| Truncated input | `[0xFF][UTF-8 "truncated input: <param>"][0x00]` | `try? output.writeUInt8(statusError)` + `try? output.writeString(...)` | same as C++ |
| Notify success | no response (Notify writes no output) | — | — |

### 3.2 Call-side request format

Written in parameter order, **with no leading status byte**:

| Type | Swift generated code |
|------|---------------|
| Integer | `try param.writeInt32(v)` |
| Float | `try param.writeDouble(v)` |
| String | `try param.writeString(v)` (automatically appends `\0` internally) |

### 3.3 Call-side response parsing

```
seek(0)
status = readUInt8()
if status != 0x00:
    msg = readString()   // scan up to \0
    throw callFailed(msg)
result = read<Type>()    // integer: read directly; string: readString()
```

### 3.4 Type mapping table

| Pascal ABI type (after normalization) | Swift type | Write | Read |
|---|---|---|---|
| `integer` / `longint` | `Int32` | `writeInt32` | `readInt32` |
| `int64` | `Int64` | `writeInt64` | `readInt64` |
| `cardinal` / `dword` / `longword` | `UInt32` | `writeUInt32` | `readUInt32` |
| `word` | `UInt16` | `writeUInt16` | `readUInt16` |
| `smallint` | `Int16` | `writeInt16` | `readInt16` |
| `byte` | `UInt8` | `writeUInt8` | `readUInt8` |
| `uint64` | `UInt64` | `writeUInt64` | `readUInt64` |
| `double` / `extended` / `real` | `Double` | `writeDouble` | `readDouble` |
| `single` | `Float` | `writeSingle` | `readSingle` |
| `string` family | `String` | `writeString` | `readString` |

### 3.5 Byte-order guarantee

Swift's `writeInt32` calls `LF_WriteInt32` underneath; the C ABI layer uses `Move(Value, buff, 4)`, which depends on the host byte order. x86_64 and arm64 are both little-endian, so this is **safe**. The Z framework itself does not support big-endian platforms (`Z.Define.inc` defines `BIG_ENDIAN` and the compile would be FATAL).

## Chapter 4 Development process and bug fix log

In chronological order, each round's bug is recorded with symptom, root cause and fix. **This is the core part of this document**.

### 4.1 Round 1: SPM identity misuse

**Symptom**:

```
error: 'complextestunit': unknown package 'LingoFuse' in dependencies of target 'ComplexTestUnit_abi_service';
       valid packages are: 'swift' (at 'D:\CoreLibrary\LingoFuse\swift')
```

**Root cause**:

The rule Swift Package Manager uses to compute the **identity** of a package registered via `.package(path:)` is: **the lowercase form of the last path component**.

For `D:\CoreLibrary\LingoFuse\swift`:
- the last component is `swift`
- identity = `swift`

But the `Package.swift` generated by `swift_abi_test_setup_generator_tool.pas` wrote:

```swift
.product(name: "LingoFuse", package: "LingoFuse")  // ❌ wrong package argument
```

The value of the `package:` argument is the `name` field of `Package.swift` (`LingoFuse`), but SPM needs the **identity** (`swift`).

**Fix**:

Added to `setup_swift_tests.ps1`:

```powershell
$packageIdentity = (Split-Path -Leaf $normalizedLingofuse).ToLower()
```

The generated `Package.swift`:

```swift
.product(name: "LingoFuse", package: "$packageIdentity")  // ✅ dynamically filled with "swift"
```

### 4.2 Round 2: wrong module name in `import`

**Symptom**:

The same as round 1 (`swift build` failed), but with a different root cause.

**Root cause**:

The test entry generated by `swift_abi_test_generator_tool.pas` used:

```swift
import ComplexTestUnitABIService   // ❌ this is the enum name
```

But Swift's `import` references the **module name** (that is, `target.name` in `Package.swift`), not the enum name inside the module.

`target.name` is `ComplexTestUnit_abi_service` (lowercase with underscores); the enum name is `ComplexTestUnitABIService` (camel case).

**Fix**:

Changed to:

```swift
import ComplexTestUnit_abi_service   // ✅ module name
```

**Fix along the way**: removed the meaningless conditional import on Windows:

```swift
// before:
#if canImport(Darwin)
import Darwin
#elseif canImport(Glibc)
import Glibc
#endif

// now: removed (Foundation already provides exit etc.)
```

### 4.3 Round 3: missing `try` on the service side's `writeUInt8`

**Symptom**:

```
error: call can throw but is not marked with 'try'
output.writeUInt8(statusOK)
```

**Root cause**:

`DataHandle.writeUInt8(_:)` is declared `throws` in `Sources/LingoFuse/DataHandle.swift`:

```swift
public func writeUInt8(_ v: UInt8) throws { ... }
```

The code generated by `EmitCallbackImpl` in `swift_abi_service_generator_tool.pas`:

```swift
output.writeUInt8(statusOK)            // ❌ missing try
output.writeUInt8(statusError)         // ❌ missing try
```

**Fix**:

```swift
try output.writeUInt8(statusOK)        // ✅
try? output.writeUInt8(statusError)    // ✅ (use try? inside catch)
```

### 4.4 Round 4: `internalCall_xxx` parameters missing external labels

**Symptom**:

```
error: missing argument labels 'a:b:' in call
let result = internalCall_MultiLineComment(uid: uid, p2pName: p2pName, a)
```

**Root cause**:

The declaration generated by `BuildInternalCallParamDecl` was:

```swift
public static func internalCall_MultiLineComment(uid: Uid, p2pName: String, a: Int32) -> Int32
```

`a: Int32` **has the external label `a`**. But the call site wrote `a` (no label):

```swift
internalCall_MultiLineComment(uid: uid, p2pName: p2pName, a)  // ❌ a has no a: prefix
```

**Fix**:

Changed the declaration to have no external label:

```swift
public static func internalCall_MultiLineComment(uid: Uid, p2pName: String, _ a: Int32) -> Int32
```

Then calling `internalCall_MultiLineComment(uid: uid, p2pName: p2pName, a)` is correct.

### 4.5 Round 5: unreachable `catch` when a Notify has no parameters

**Symptom**:

```
warning: 'catch' block is unreachable because no errors are thrown in 'do' block
```

**Root cause**:

When a Notify has no parameters, the `do { } catch { }` block contains only `internalNotify_xxx(...)` (not throws), so `catch` is never reachable.

**Fix**:

`EmitCallbackImpl` gained a condition:

```pascal
NeedTryBlock := F.IsFunction or HasParams;
if NeedTryBlock then
  Lines.Add('        do {');
```

For a Notify with no parameters it now generates:

```swift
private static func callback_ExternalAlias(input: DataHandle) {
    let uid = input.p2pUid()
    let p2pName = input.p2pName()
    internalNotify_ExternalAlias(uid: uid, p2pName: p2pName)
}
```

No `do-catch` wrapper.

### 4.6 Round 6: `P2P.registerCall` external label difference

**Symptom**:

```
error: missing argument labels 'description:handler:' in call
try P2P.registerCall("NoParamFunc", "...", callback_NoParamFunc)
```

**Root cause**:

`AppHandle.registerCall` and `P2P.registerCall` have **different external label semantics**:

```swift
// AppHandle.swift
public func registerCall(
    _ apiName: String,
    _ description: String = "",       // no external label
    _ handler: @escaping (...) -> Void // no external label
) throws -> Bool

// P2P.swift
public static func registerCall(
    _ apiName: String,
    description: String = "",          // has external label
    handler: @escaping (...) -> Void   // has external label
) throws -> Bool
```

**Fix**:

Added external labels to the P2P call in `EmitRegisterAll`:

```pascal
Lines.Add('        try P2P.registerCall(' + SwiftStrLit(ApiName) + ', description: ' + SwiftStrLit(Description) +
  ', handler: callback_' + ApiName + ')')
```

The `AppHandle` call keeps no labels:

```pascal
Lines.Add('        try app.registerCall(' + SwiftStrLit(ApiName) + ', ' + SwiftStrLit(Description) +
  ', callback_' + ApiName + ')')
```

### 4.7 Round 7: a genuine unused warning on `let msg = ...`

**Symptom**:

```
warning: initialization of immutable value 'msg' was never used
let msg = (try? resp.readString()) ?? ""
```

**Root cause**:

`LingoFuseError.callFailed(operation:targetApp:targetApi:)` **has no message parameter**, so `msg` had nowhere to go.

**Fix**:

Concatenated `msg` into `operation`:

```swift
let msg = (try? resp.readString()) ?? ""
throw LingoFuseError.callFailed(
    operation: "ABI call \(apiName) failed: " + msg,   // ✅ msg is now used
    targetApp: targetAppName,
    targetApi: apiName)
```

### 4.8 Round 8: `swift run <Product>` is case-sensitive

**Symptom**:

```
error: no executable product named 'ServiceTest'
```

**Root cause**:

The product name in `Package.swift` was `service_test` (lowercase):

```swift
.executable(name: "service_test",    targets: ["ServiceTest"]),
```

But the user typed `swift run ServiceTest` (capital first letter); SPM is **case-sensitive**, so they did not match.

**Fix**:

```swift
.executable(name: "ServiceTest",    targets: ["ServiceTest"]),   // ✅ consistent with the target name
.executable(name: "CallTest",       targets: ["CallTest"]),
```

### 4.9 Round 9: FPC compile error `String exceeds line`

**Symptom**:

```
swift_abi_call_generator_tool.pas(381,103) Fatal: (2001) String exceeds line
```

**Root cause**:

In `swift_abi_call_generator_tool.pas`:

```pascal
Lines.Add('                operation: ' + SwiftStrLit('ABI call ' + ApiName.Text + ' failed: ') + ' + msg,');
```

This is a **5-part string concatenation** (`literal + function call + literal + literal,`), and the last part `' + msg,'` contains the `+` and `,` characters. FPC 3.2.2 triggers a column-number check error in this edge case.

**Fix**:

Switched to a local `OpLine` variable and appended step by step:

```pascal
procedure EmitReadResponseHelper(...);
var
  OpLine: TP_String;
begin
  ...
  OpLine := '                operation: ';
  OpLine.Append(SwiftStrLit('ABI call ' + ApiName.Text + ' failed: '));
  OpLine.Append(' + msg');
  OpLine.Append(',');
  ...
  Lines.Add(OpLine.Text);   // ✅ single argument, the simplest FPC parse path
end;
```

**Same treatment**: the `Lines.Add('literal' + Func(...) + 'literal',')` in `EmitSyncAppCall` / `EmitSyncUidCall` / `EmitSyncP2PNameCall` was also changed to step-by-step appends.

### 4.10 Round 10: `LF_LoadLibrary` was never called

**Symptom**:

```
LingoFuse: SetOption called before LF_LoadLibrary
LingoFuse: ResetPrepare called before LF_LoadLibrary
LingoFuse: PrepareService called before LF_LoadLibrary
LingoFuse: CreateApp called before LF_LoadLibrary
[FATAL] service test: \(error)\n
LingoFuse: ExitMainThread called before LF_LoadLibrary
LingoFuse: Shutdown called before LF_LoadLibrary
```

**Root cause**:

The test entry generated by `swift_abi_test_generator_tool.pas` **omitted the `LF_LoadLibrary` call**. Referring to `Sources/LingoFuse/Framework.swift` and `CrossService/main.swift`, **the C ABI layer must explicitly load the dynamic library**.

**Fix**:

Service test top level:

```swift
print("=== ... ===")
if LF_LoadLibrary() != 1 {
    FileHandle.standardError.write("[FATAL] LF_LoadLibrary failed\n".data(using: .utf8)!)
    exit(1)
}
let SERVICE_TEST_EXIT_CODE: Int32 = serviceTestRun()
LF_FreeLibrary()
if SERVICE_TEST_EXIT_CODE != 0 { exit(SERVICE_TEST_EXIT_CODE) }
```

The call test top level is the same.

### 4.11 Round 11: Free Pascal has no `\\` escape

**Symptom**:

```
=== ComplexTestUnit ABI service test ===
LingoFuse: SetOption called before LF_LoadLibrary
...
[FATAL] service test: \(error)\n
```

Note that the output is the literal `\(error)\n` rather than `"the real error message\n"`.

**Root cause**:

Free Pascal **has no C-style `\\` escape**. In Pascal:

- `'\'` is **two backslash characters** (not "one backslash")
- `''` is **one backslash character**

`swift_abi_test_generator_tool.pas` wrote:

```pascal
Lines.Add('        FileHandle.standardError.write("[FATAL] service test: \\(error)\\n".data(using: .utf8)!)');
```

The generated Swift source was:

```swift
FileHandle.standardError.write("[FATAL] service test: \\(error)\n".data(using: .utf8)!)
```

The Swift compiler escapes `\\` to `\` and `\n` to a newline. So the final runtime string was `"[FATAL] service test: \(error)" + newline`, and `\(error)` was **literal text**, not interpolation.

**Fix**:

Changed every `'...\\...'` to `'...\...'` (a single backslash), so the generated Swift source is:

```swift
FileHandle.standardError.write("[FATAL] service test: \(error)\n".data(using: .utf8)!)
```

and the Swift compiler interpolates correctly.

**Specific locations** (all of them):
- `serviceTestCbWhoAmI`'s `print("[SERVICE] whoami: p2p=\(p2p)")`
- `serviceTestCbAskCallMe`'s `print("[SERVICE] ask_call_me: client did not respond \(error)")`
- the 4 places in `serviceTestRun`
- `EmitSyncCallTest`'s `"\(r)"` / `"\(error)"`
- `EmitAsyncCallTest`'s `"\(v)"` / `"\(e)"`
- `EmitSyncNotifyTest`'s `"\(error)"`
- all `\(...)` and `\n` in the call test

### 4.12 Round 12: Swift↔Swift failure (missing wait for the Target to be ready)

**Symptom**:

- **Pascal call → Swift service**: all PASS ✅
- **Swift call → Swift service**: failed ❌

CallTest output:

```
Connection ipc:ComplexTestUnit_abi:0 Succeeded
[READY] Client online.

"ComplexTestUnit_abi" no connection             ← ❌ target not found
[WARN] whoami failed, UID tests will be skipped

Ready Network: "ipc:ComplexTestUnit_abi"        ← async log: the connection only now truly becomes Ready
APP LF_TEST_CLIENT_SELF "client test app" Ready OK
```

**Root cause**:

- **The Pascal client defaults to `Wait_Connection_ReadyOk=True`**: `LF_PrepareDone` **blocks waiting** for all clients to be Ready and only returns after the C4-layer handshake completes. By then the Target App's broadcast has already reached the client cache, so `Framework.call` routes correctly.
- **The Swift client sets `Wait_Connection_ReadyOk=False`**: `LF_PrepareDone` **returns immediately**. At that point TCP is connected, but **the C4-layer App registration broadcast (server App → client cache) has not finished propagating**. `Framework.call` routing by App name cannot find the Target and returns "no connection".
- **A few seconds later** (when the async log `Ready Network: "ipc:..."` is printed) the connection truly becomes Ready. But `callTestProbeClientIdentity` has already failed and exited.

**Compared with the Rust version**: `GenerateABICallTestRsCode` in `rust_abi_test_generator_tool.pas` **does** have a wait loop:

```rust
let mut ready = false;
for _ in 0..30 {
    if framework::check_api(DEFAULT_TARGET_APP, WHOAMI_API).unwrap_or(false) {
        ready = true;
        break;
    }
    std::thread::sleep(Duration::from_millis(200));  // 30 × 200ms = 6 seconds
}
```

**The Swift version omitted this block**.

**Fix**:

In `callTestRun` of `GenerateABICallTestSwiftCode`, after `print("[READY] Client online.")` and before `callTestProbeClientIdentity()`, added 11 lines:

```swift
var targetReady = false
for _ in 0..<30 {
    if Framework.checkApi(CALL_TEST_TARGET_APP, CALL_TEST_WHOAMI_API) {
        targetReady = true
        break
    }
    Thread.sleep(forTimeInterval: 0.2)
}
if targetReady {
    print("[OK] Target service ready on the mesh")
} else {
    FileHandle.standardError.write("[WARN] Target service not ready on the mesh\n".data(using: .utf8)!)
}
print("")
```

**Why only CallTest was fixed, not ServiceTest**:
- ServiceTest is the server side; after `prepareDone` returns it is already Listening and does not proactively call a Target, so no waiting is needed.
- CallTest is the client side and must wait for the Target App's broadcast to arrive before routing can succeed.

**Verification after the fix**: Swift call → Swift service all PASS ✅

## Chapter 7 Key decision log

### 7.1 The service side does not use `@convention(c)` / `@_cdecl`

**Decision**: the service-side callback passes the function reference straight to `AppHandle.registerCall`, with no hand-written trampoline.

**Rationale**:
- `Sources/LingoFuse/AppHandle.swift` already wraps `swiftCallTrampoline` / `swiftNotifyTrampoline` (`@convention(c)` closures)
- `@_cdecl` across files on Windows causes duplicate definitions (`lld-link: duplicate symbol`), so `@convention(c)` is used to avoid it
- The generated code is cleaner and the user does not have to care about trampolines

### 7.2 `internalCall_*` uses a `fatalError` placeholder

**Decision**: `internalCall_*` / `internalNotify_*` generate `fatalError("TODO: ...")` by default; the user must implement them by hand.

**Rationale**:
- **Consistent with C++/Pascal/Rust**: C++ generates `return 0;`, Pascal generates `Result := default`, Rust generates `fatalError`. That is the role of an ABI generator.
- Auto-generating an "echo-style default implementation" (e.g. `Add` returning `a+b`) would deviate from the semantics of an ABI generator and make cross-language behavior inconsistent.

### 7.3 `Package.swift` is generated at runtime (not pre-generated)

**Decision**: `setup_swift_tests.ps1` generates `Package.swift` at runtime rather than the generator producing it in advance.

**Rationale**:
- SPM's `.package(path:)` needs an absolute path (relative paths break when moving machines)
- `Package.swift` is read at Swift compile time and cannot read environment variables
- So it must be resolved and pinned at setup-script runtime with `Resolve-Path`

### 7.4 Async tests use `Task.detached + DispatchSemaphore`

**Decision**: the call test's async API tests use `Task.detached + DispatchSemaphore` to convert to synchronous.

**Rationale**:
- **No main-thread RunLoop dependency**: `Task.detached` runs on the Swift Cooperative Thread Pool, avoiding the complexity of main-thread RunLoop driving
- **Safe**: blocking the main thread with `DispatchSemaphore.wait` is safe (the test program has no watchdog)
- **Aligned with Rust's `mpsc::channel + recv_timeout`**: mechanically equivalent

**Why not `Task { ... }`**: `Task {}` inherits the current actor context and may fall back to the main actor, blocking the main thread. `Task.detached` clearly detaches.

### 7.5 The Swift 6.4 `#NoUsage` warning is not fixed

**Decision**: the unused warning on `let r = try ...; "\(r)"` is **not fixed**.

**Rationale**:
- These variables are clearly used in string interpolation; Swift 6.4's `#NoUsage` misjudges "used only in print string interpolation" as unused
- Fixing would require `_ = r` or embedding `"\(try ...)"` directly, introducing ugly code
- Users on Swift 6.3 or earlier see no such warning
- It is an aggressive Swift 6.4 diagnostic, not a code bug

**If the user demands a clean build**:
- Option A: use Swift 6.3 or earlier
- Option B: refactor the test generator to change `let r = ...` to `"\(try ...)"` with direct embedding (higher cost)

### 7.6 Application-level compensation for `Wait_Connection_ReadyOk=False`

**Decision**: the Swift call test sets `Wait_Connection_ReadyOk=False`, but **must** add the wait loop `for _ in 0..<30 { checkApi; sleep 0.2 }`.

**Rationale**:
- With `True`, `prepareDone` blocks and waits, slowing startup (30-second timeout)
- With `False`, `prepareDone` returns immediately, so the application layer must poll `checkApi` to compensate for the C4-layer broadcast delay
- **The Rust version already does this**; the Swift version aligns
