## 1. The Service library's responsibilities and lifecycle

### 1.1 The Service library's responsibilities

The Service library responds **passively** to the caller:

1. **register** the declared APIs on the LingoFuse App;
2. **decode** the binary requests coming from the call side;
3. **invoke** the user-implemented `internal_call_<Api>` stub;
4. **encode** the return value (or error) as a binary response;
5. provide **notify callbacks** (with no return value);
6. support **actively calling back the client** (optional scenarios such as `LF_TEST_ASK_SERVICE_CALL_ME`).

### 1.2 Lifecycle (consistent across languages)

```
┌──────────────────────────────────────────────────────────────┐
│  1. LF_ResetPrepare()                                        │
│  2. LF_PrepareService(listenAddr, physicsAddr)               │
│  3. LF_CreateApp(DEFAULT_APP_NAME, DEFAULT_APP_DESC)         │
│  4. Register_All_ABI_APIs(App)      ← user API registration  │
│  5. LF_RegisterCall / Notify (helper APIs, optional)         │
│  6. LF_PrepareClient(endpoint, App)                          │
│  7. LF_PrepareDone()                                         │
│  8. (event loop)                                             │
│  9. LF_ExitMainThread()                                      │
│ 10. LF_FreeApp(App)                                          │
│ 11. LF_Shutdown()                                            │
└──────────────────────────────────────────────────────────────┘
```

**Step 4 is the core**: `Register_All_ABI_APIs` is provided by the generator and registers every routine in the source unit as a LingoFuse API. Internally it walks all APIs and calls `LF_RegisterCall` (for those with a return value) or `LF_RegisterNotify` (for those without).

### 1.3 Callback thread model

**Service callbacks in every language execute on a LingoFuse worker thread** (not the main thread). That means:

- the body of the `internal_call_<Api>` stub runs on a worker thread;
- `Callback_<Api>` runs on a worker thread;
- a callback must not block, and must not call blocking LingoFuse interfaces;
- to touch the UI or access non-thread-safe resources, you must switch back to the main thread.

### 1.4 Differences from the Call library

| Dimension | Service library | Call library |
|------|-----------|---------|
| Role | Passive responder | Active initiator |
| Trigger | Triggered by LingoFuse workers | Triggered by user code |
| Main APIs | `Register_All_ABI_APIs` / `internal_call_<Api>` | `Foo` / `Foo_Async` / ... |
| Return value handling | Written by the callback into the Out handle | Read by the caller |
| Threads | Callbacks on worker threads | Synchronous calls on the user thread; async callbacks on worker threads |

## 2. Cross-language unified concepts

### 2.1 The three core API categories

Whatever the language, the service library generates the following three kinds of entry points:

| Category | Generated content | Notes |
|------|----------|------|
| **Internal call stub** | `internal_call_<Api>(uid, p2p_name, [args])` | **The user fills in the implementation**; LingoFuse calls this stub when a request arrives |
| **LingoFuse callback** | `Callback_<Api>(in, out)` (Call) / `Callback_<Api>(in)` (Notify) | **Do not modify**; decodes, calls the stub, encodes the response |
| **Registration function** | `Register_All_ABI_APIs(app)` / `Register_All_P2P_ABI_APIs()` | **Do not modify**; registers all APIs in bulk |

Some languages additionally provide `Create_And_Register_ABI_App()`, a convenience function doing CreateApp + RegisterAll in one step.

### 2.2 App naming conventions

The service library in every language injects two constants at generation time:

| Constant | Value |
|------|-----|
| `DEFAULT_APP_NAME` | `<UnitName>_abi` |
| `DEFAULT_APP_DESC` | `ABI service for <UnitName>` |

These constants are used for `LF_CreateApp`. For cross-process calls, **the `ABI_TargetApp` on the call side must match**.

### 2.3 Wire protocol (consistent across languages)

The Service library processes each request in this order:

1. read `uid` (32 bytes) and `p2p_name` (UTF-8, NUL-terminated) from the `in` handle;
2. decode each parameter in parameter-table order;
3. call `internal_call_<Api>(uid, p2p_name, [args])`;
4. write the response as `[status:uint8_t][payload]`:
   - `0x00` + serialized result (function);
   - `0x00` (procedure);
   - `0xFF` + UTF-8 error message (exception).

### 2.4 P2P group registration

`Register_All_P2P_ABI_APIs()` registers the APIs on the P2P group so the call side can locate the service by P2P group name (instead of App name or UID). Before calling it you must call `LF_Set_Opt_P2P_Name("<UnitName>_service_test_p2p")` (the method name differs slightly per language).

| LingoFuse callback | `Callback_<Api>(_Trigger, _In_, _Out_) cdecl` (Call)<br>`Callback_<Api>(_Trigger, _In_) cdecl` (Notify) |
| Registration | `Register_All_ABI_APIs(App: TAppHnd___)` |
| Registration | `Register_All_P2P_ABI_APIs()` |
| Convenience | `Create_And_Register_ABI_App: TAppHnd___` |

**Development platform**

| Item | Requirement |
|------|------|
| Compiler | Free Pascal 3.2+ / Delphi 10.4+ |
| Language mode | Delphi mode (`{$mode delphi}`) |
| Source encoding | UTF-8 (`{$CODEPAGE UTF8}`) |

**OS**: Windows / Linux / macOS.

**Dependencies**

| Dependency | How to include |
|------|----------|
| `lingofuse_import.pas` | `-Fu<dir-with-lingofuse_import.pas>` |
| `Z.Core` | `-Fu<dir-with-Z.Core.pas>` |
| `lingofuse_helper.pas` (optional) | `-Fu<dir-with-lingofuse_helper.pas>` |

**Integration code**

```pascal
uses
  SysUtils,
  lingofuse_import,
  <Unit>_abi_service_unit;

// 1. Fill in the internal_call stub body
function <Unit>_abi_service_unit.internal_call_Foo(
  UID___: TP2P_UID___; p2pName___: string;
  a: Integer; b: Integer): Integer;
begin
  // call the real business function
  Result := a + b;
end;

// 2. Start the service
var
  App: TAppHnd___;
begin
  LF_ResetPrepare();
  LF_Set_Opt_Quiet(True);
  LF_Set_Opt_ConsoleOutput(True);

  LF_PrepareServiceEx('ipc:<Unit>_abi', 'ipc:<Unit>_abi');

  App := LF_CreateAppEx(DEFAULT_APP_NAME, DEFAULT_APP_DESC);
  if App = nil then
  begin
    WriteLn('CreateApp failed');
    Halt(1);
  end;

  // register all APIs (user APIs plus stubs)
  Register_All_ABI_APIs(App);

  // register the test helper APIs (optional, used for UID probing on the call side)
  LF_RegisterCallEx(App, 'LF_TEST_WHOAMI',
    'service-side whoami helper', nil, @Test_CB_WHOAMI);
  LF_RegisterNotifyEx(App, 'LF_TEST_ASK_SERVICE_CALL_ME',
    'ask service to call back client', nil, @Test_CB_ASK_SERVICE_CALL_ME);

  // register the P2P group
  LF_Set_Opt_P2P_Name('<Unit>_service_test_p2p');
  Register_All_P2P_ABI_APIs();

  // connect to the IPC endpoint
  if LF_PrepareClientEx('ipc:<Unit>_abi', App) = -1 then
  begin
    LF_FreeApp(App);
    Halt(1);
  end;

  if LF_PrepareDone() <> 1 then
  begin
    LF_ExitMainThread();
    LF_FreeApp(App);
    LF_Shutdown();
    Halt(1);
  end;

  WriteLn('[OK] service ready');
  ReadLn;  // press Enter to stop

  // 3. Shut down
  LF_ExitMainThread();
  LF_FreeApp(App);
  LF_Shutdown();
end.
```

**Cautions**

- **`LF_RegisterCallEx` vs `LF_RegisterNotifyEx`**: the former is for functions with a return value, the latter for procedures.
- **`Callback_<Api>` signature**: the Call type is `(_Trigger, _In_, _Out_)`, the Notify type is `(_Trigger, _In_)`; the `cdecl` calling convention is used.
- **UID type**: `TP2P_UID___` is `array[0..31] of Byte`.
- **`DEBUG_LOG`**: when set to `True`, callbacks print diagnostic information.

**Integration code**

```python
from lingofuse._lf_native import (
    LF_ResetPrepare, LF_PrepareService, LF_PrepareClient,
    LF_PrepareDone, LF_CreateApp, LF_RegisterCall, LF_RegisterNotify,
    LF_ExitMainThread, LF_FreeApp, LF_Shutdown,
)
from lingofuse.lf_io import cstr
import <Unit>_abi_service as svc

# 1. Fill in the internal_call stub body
def _patched_internal_call_Foo(_lf_uid, _lf_p2p_name, a, b):
    return a + b

svc.internal_call_Foo = _patched_internal_call_Foo

# 2. Start the service
LF_ResetPrepare()
LF_PrepareService(cstr("ipc:<Unit>_abi"), cstr("ipc:<Unit>_abi"))

app = svc.Create_And_Register_ABI_App()
if app is None:
    raise SystemExit(1)

# optional: register the test helper APIs
LF_RegisterCall(app, cstr("LF_TEST_WHOAMI"),
                cstr("whoami helper"), None, my_whoami_cb)
LF_RegisterNotify(app, cstr("LF_TEST_ASK_SERVICE_CALL_ME"),
                  cstr("ask service to call back client"), None, my_ask_cb)

# register P2P
from lingofuse.lf_io import cstr as _c
from lingofuse._lf_native import LF_Set_Opt_P2P_Name
LF_Set_Opt_P2P_Name(_c("<Unit>_service_test_p2p"))
svc.Register_All_P2P_ABI_APIs()

if LF_PrepareClient(cstr("ipc:<Unit>_abi"), app) == -1:
    raise SystemExit(1)
if LF_PrepareDone() != 1:
    raise SystemExit(1)

print("[OK] service ready")
input()  # press Enter to stop

# 3. Shut down
LF_ExitMainThread()
LF_FreeApp(app)
LF_Shutdown()
```

**Cautions**

- **How to replace the `internal_call_<api>` stub**: Python has no function forward declaration, so you simply **reassign** `svc.internal_call_Foo = _patched_internal_call_Foo` (or, more elegantly, subclass the `svc` module).
- **`@LFCallFunc` / `@LFNotifyFunc`**: decorators that turn ordinary Python functions into ctypes-compatible callbacks; `Create_And_Register_ABI_App()` has already registered all the `Callback_<api>` functions internally.
- **`internal_call` signature**: the first parameter is `_lf_uid` (`bytes`, 32 bytes), the second is `_lf_p2p_name` (`str`); the user parameters follow.
- **Return value**: just `return`; the framework encodes it.
- **`DEBUG_LOG`**: when set to `True`, callbacks print diagnostic information.

|------|----------|

**Integration code**

```cpp
#include "<Unit>_abi_service.hpp"
#include "LingoFuse.hpp"
#include "lf_io.hpp"

// 1. Fill in the internal_call stub body
namespace <Unit>_abi {
int64_t internal_call_Foo(
    const std::array<std::uint8_t, 32>& _lf_uid,
    const std::string& _lf_p2p_name,
    int64_t a, int64_t b) {
  (void)_lf_uid;
  (void)_lf_p2p_name;
  return a + b;
}
}  // namespace <Unit>_abi

// 2. Start the service
int main() {
  if (LF_LoadLibrary() != 1) {
    std::fprintf(stderr, "[FATAL] LF_LoadLibrary failed\n");
    return 1;
  }

  LF_ResetPrepare();
  LF_Set_Opt_Quiet(1);
  LF_Set_Opt_ConsoleOutput(1);
  LF_PrepareService("ipc:<Unit>_abi", "ipc:<Unit>_abi");

  TAppHnd app = <Unit>_abi::Create_And_Register_ABI_App();
  if (app == nullptr) {
    std::fprintf(stderr, "[FATAL] Create_And_Register_ABI_App failed\n");
    LF_Shutdown();
    LF_FreeLibrary();
    return 1;
  }

  // optional: register the test helper APIs
  LF_RegisterCall(app, "LF_TEST_WHOAMI",
                  "whoami helper", nullptr, &MyWhoAmICb);
  LF_RegisterNotify(app, "LF_TEST_ASK_SERVICE_CALL_ME",
                    "ask service to call back client", nullptr, &MyAskCb);

  // P2P
  LF_Set_Opt_P2P_Name("<Unit>_service_test_p2p");
  <Unit>_abi::Register_All_P2P_ABI_APIs();

  if (LF_PrepareClient("ipc:<Unit>_abi", app) == -1) {
    std::fprintf(stderr, "[FATAL] PrepareClient failed\n");
    LF_FreeApp(app);
    LF_Shutdown();
    LF_FreeLibrary();
    return 1;
  }

  if (LF_PrepareDone() != 1) {
    LF_ExitMainThread();
    LF_FreeApp(app);
    LF_Shutdown();
    LF_FreeLibrary();
    return 1;
  }

  std::printf("[OK] service ready\n");
  std::getchar();

  // 3. Shut down
  LF_ExitMainThread();
  LF_FreeApp(app);
  LF_Shutdown();
  LF_FreeLibrary();
  return 0;
}
```

**CMake integration**

```cmake
cmake_minimum_required(VERSION 3.15)
project(my_service LANGUAGES CXX C)
set(CMAKE_CXX_STANDARD 17)

find_package(Threads REQUIRED)

add_library(lingofuse_c_wrapper STATIC ${LINGOFUSE_CPP_DIR}/LingoFuse.c)
target_include_directories(lingofuse_c_wrapper PUBLIC ${LINGOFUSE_CPP_DIR})

add_library(<Unit>_abi_service STATIC <Unit>_abi_service.cpp)
target_include_directories(<Unit>_abi_service PUBLIC ${CMAKE_CURRENT_SOURCE_DIR})
target_link_libraries(<Unit>_abi_service PUBLIC lingofuse_c_wrapper Threads::Threads)

add_executable(my_service main.cpp)
target_link_libraries(my_service PRIVATE <Unit>_abi_service)
```

**Cautions**

- **`LF_LoadLibrary()`**: must be called first; a return of 1 means success.
- **The `Safe_Write_*` family**: provided by the generator for safely writing responses inside callbacks; do not use raw `LF_WriteBuffer`.
- **`LF_RegisterCall` / `LF_RegisterNotify`**: Call is for functions, Notify for procedures.
- **Callback signature**: `void LF_CDECL Callback_<Api>(void*, void*, void*)` (Call) or `(void*, void*)` (Notify).
- **MSVC**: `/utf-8` is mandatory, otherwise the API description strings are encoded in the system codepage.

    ok = lingofuse:reset_prepare(),

        {ok, _} -> ok;
        _ -> halt(1)
    end,
    {ok, 1} = lingofuse:prepare_done(),

    io:format("[OK] service ready~n"),

loop(App) ->
    receive
        {lf_call, Ref, Api, Payload, Identity} when is_integer(Ref) ->
            _ = '<Unit>_abi_service':lf_dispatch_call(Api, Ref, Payload, Identity),
            loop(App);
        {lf_call, Ref, Api, Payload} when is_integer(Ref) ->
            _ = '<Unit>_abi_service':lf_dispatch_call(Api, Ref, Payload, #{}),
            loop(App);
        {lf_notify, Api, Payload, Identity} when is_binary(Api) ->
            _ = '<Unit>_abi_service':lf_dispatch_notify(Api, Payload, Identity),
            loop(App);
        {lf_notify, Api, Payload} when is_binary(Api) ->
            _ = '<Unit>_abi_service':lf_dispatch_notify(Api, Payload, #{}),
            loop(App);
        _Other ->
            loop(App)
    end.

## 5. Cautions for Service–Call cooperation

### 5.1 Endpoint consistency

| Item | Service side | Call side |
|------|-----------|---------|
| Endpoint | `ipc:<Unit>_abi` | `ipc:<Unit>_abi` |
| App name | `DEFAULT_APP_NAME = "<Unit>_abi"` | `ABI_TargetApp = "<Unit>_abi"` |
| P2P group | `LF_Set_Opt_P2P_Name("<Unit>_service_test_p2p")` | `ABI_TargetP2P = "<Unit>_service_test_p2p"` |

**Any mismatch causes `EABI_RemoteError: nil response (timeout or target not found)`.**

### 5.2 UID probing

`LF_TEST_WHOAMI` + `LF_TEST_ASK_SERVICE_CALL_ME` form the **cooperation protocol** by which the call side obtains the service UID:

1. the call side sends an `LF_TEST_WHOAMI` request;
2. the service-side callback returns its own UID;
3. the call side caches the UID for the later `_UID_Call` variants.

**If the service side does not register `LF_TEST_WHOAMI` and `LF_TEST_ASK_SERVICE_CALL_ME`**:

- the `_UID_Call` / `_UID_Async` / `_UID_AsyncSequenced` variants are all `[SKIP]`;
- the other variants (App / P2P) are unaffected.

### 5.3 Reverse calling (service → client)

`LF_TEST_ASK_SERVICE_CALL_ME` is the cooperation protocol by which the service **actively calls** the client:

1. the call side sends an `LF_TEST_ASK_SERVICE_CALL_ME` notification;
2. the service-side callback **does not return immediately**, but issues an `LF_TEST_REPORT_SERVICE_IDENTITY` call to the client;
3. the client-side callback receives the request and returns its own identity information;
4. the service side obtains the client's UID / P2P name (for reverse calls).

**This protocol depends on the call side registering an `LF_TEST_REPORT_SERVICE_IDENTITY` callback**; if it is not registered, the service's reverse call times out, but this **does not affect** the call side's `_UID_Call` variants (the UID was already obtained in step 2 through `LF_TEST_WHOAMI`).

### 5.4 Thread model comparison

| Scenario | Service side | Call side |
|------|-----------|---------|
| App / P2P / UID synchronous call | — | user thread |
| App / P2P / UID asynchronous call | — | initiated on the user thread, callback on a worker thread |
| Service callback | worker thread | — |
| Service reverse-calling the client | inside the callback (worker thread) | routed by LingoFuse to the client's callback |

**Key constraint**: **do not call blocking LingoFuse interfaces inside a callback**. If a service callback needs to actively call another service, it must:

1. dispatch the call to a separate thread (`std::thread` / `Task.Run` / `TThread.CreateAnonymousThread` / `spawn` / `Threads.@spawn`);
2. or, inside the callback, only use a "register then call" pattern with `LF_Register*` (supported in some languages).

### 5.5 Lifecycle order

**Service side**:

```
LF_ResetPrepare
  → LF_PrepareService
  → LF_CreateApp
  → Register_All_ABI_APIs
  → LF_RegisterCall / Notify (helper APIs)
  → LF_Set_Opt_P2P_Name + Register_All_P2P_ABI_APIs
  → LF_PrepareClient
  → LF_PrepareDone
  → [event loop]
  → LF_ExitMainThread
  → LF_FreeApp
  → LF_Shutdown
```

**Call side**:

```
LF_ResetPrepare
  → LF_PrepareClient
  → LF_PrepareDone
  → [call APIs]
  → LF_ExitMainThread
  → LF_Shutdown
```

**Wrong ordering** (for example `LF_PrepareDone` before `LF_PrepareClient`) makes `prepareDone` return something other than 1.

## 6. Frequently asked questions

### Q1: What is the difference between the Service library and the Call library?

The **Service library** is the **passive responder**: register APIs, decode requests, invoke the `internal_call_<Api>` stub, encode responses. The **Call library** is the **active initiator**: it exposes functions such as `Foo` / `Foo_Async` for the user to call.

Full two-way communication requires **both ends running**: the service process starts and listens on the endpoint, and the call process connects to the endpoint and issues requests.

### Q2: Must the `internal_call_<Api>` stub be implemented?

**Yes.** What the generator emits is a placeholder stub that **returns default values**; if you do not fill it in, it returns `0` / `0.0` / `""` / `null` and the business logic never runs.

- **Pascal / C++ / Rust / Go / Java / Zig / Swift / Ruby / Fortran / R**: edit the generated source file directly to fill in the stub body;
- **Python / Node.js / TypeScript / Julia**: replace the stub body by **reassigning / registering a function** (without touching the source file);
- **C#**: fill it in inside the `InternalCalls` partial class (a separate file is required);
- **Dart**: edit the generated `.dart` file directly.

### Q3: Can service callbacks execute on the main thread?

**No.** LingoFuse's worker model requires callbacks to run on worker threads; if a callback needs to access the UI or non-thread-safe resources, it must **switch back to the main thread** (see `code_decl_to_abi_CALL_LIBRARY_INTEGRATION.md` §4.5 for the approach per language).

### Q4: What does `Register_All_ABI_APIs` do?

It walks all APIs and, for each, calls `LF_RegisterCall` (function) or `LF_RegisterNotify` (procedure), with the parameters:

- `App`: the handle returned by `LF_CreateApp`;
- `ApiName`: the name normalized by the generator with `MakeApiName`;
- `Description`: the first line extracted from the source comment (truncated to 200 characters);
- `UserData`: `nil` / `null`;
- `Callback`: the `Callback_<Api>` function pointer.

The return value is the **failure count** (C++ / Go / Java / R) or a **side effect** (Pascal / Python / Ruby and others have no return value).

### Q5: Why register `LF_TEST_WHOAMI` and `LF_TEST_ASK_SERVICE_CALL_ME`?

They are the **cooperation protocol** by which the call side obtains the service UID (see §5.2). **They can be omitted in production**, but **registering them in test environments is recommended**, otherwise the call side's `_UID_*` variants are all SKIP and coverage drops.

### Q6: Can the service side call other services?

**Yes**, but **not synchronously inside a callback** (that deadlocks). The correct approach:

1. inside the callback, **dispatch the request to a separate thread**;
2. on that separate thread, call the target service with `LF_Call` / `LF_Notify`;
3. pass the result back through a thread-safe queue / Future / Promise.

The async models of some languages (Python / Node.js / Dart / Julia) naturally suit this "async call inside a callback" pattern, but **initiating blocking calls directly on a worker thread is still not recommended**.

### Q7: What must the service change for mixed-language deployment?

**Nothing.** The wire protocol is language-agnostic; a service in any language can be called by a client in any language. You only need:

- both ends generated from **the same source unit**;
- matching endpoint, App name and P2P group name;
- matching runtime libraries.

### Q8: Does the Service library support "registering only some of the APIs"?

**Yes.** You can call `LF_RegisterCall` / `LF_RegisterNotify` manually to register only some APIs instead of calling `Register_All_ABI_APIs`. But note:

- APIs that are not registered time out on the call side;
- manual registration means you manage the pointer lifetime of `Callback_<Api>` yourself (C# / Node.js especially must watch for GC).

### Q9: How do I confirm the service is listening after it starts?

- check the `LF_PrepareDone` return value: `1` means ready;
- look for the log line `[OK] service ready`;
- a call to `LF_CheckApp(<Unit>_abi)` from the call side returning `True` means the service is visible.

### Q10: Can Swift on Windows be used in production?

**Not recommended.** Swift 5.9+ officially provides a Windows toolchain, but:

- the `LingoFuse` Swift package is currently mainly verified on macOS and Linux;
- for production prefer macOS (first choice) / Linux (second);
- on Windows, prefer C++ / C# on the service side.
